# Тест-план (короткий)

## Объекты

1. Форма регистрации. Ключевое правило — только 18+. Чекбокс новостей не обязательный.
2. Окно конфигуратора компонента. Пять функций: добавить опцию, удалить, поменять порядок опций и свойств, поиск, стандартное поведение окна.

## Что проверил

- регистрацию: границы возраста (17/18/19), пустые поля, email, пароль и подтверждение, новости выбраны/не выбраны, двойная отправка;
- конфигуратор: обязательные опции «Наименование» и «Система координат модели», серый цвет добавленных опций, повторное добавление, удаление, порядок, поиск, сохранение;
- окружение: Windows 11 и Ubuntu 24.04, масштабы 100–200%, кириллица/латиница.

## Границы

- реального ПО нет — только скриншоты из ТЗ. Поэтому проверял «как если бы»: поведения, которые в ТЗ не описаны, вынес в допущения и вопросы, а не дофантазировал.
- нагрузку, безопасность сети, авторизацию через соцсети не трогал — это не в скоупе ТЗ.

## Риски

- ТЗ не указывает правила пароля, алгоритм возраста, что делать со значениями после удаления опции. Пока нет ответов — часть проверок будет на допущениях.
- Часть багов (несколько серых опций, повторное добавление) не воспроизводится на скриншоте, потому что скриншот статичный. Оформил как вероятные, пометил.

## Критерии готовности

Хай-проверки закрыты, блокеры либо исправлены, либо отложены с решением, вопросы по неясным правилам зафиксированы.
